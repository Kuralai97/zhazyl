# DORA метрикаларының анықтамалары және бұтақ ережесі

Бұл анықтамалар өзгермейді. Өзгерсе, бұрынғы және жаңа өлшемдерді салыстыруға болмайды.

## Анықтамалар
| Термин | Біздің жобада |
|---|---|
| Орналастыру (deployment) | main бұтағындағы CI-дың сәтті өтуі: барлық тексеру жасыл, Docker образы құрастырылды, `zhazyl-<sha>` артефакты жарияланды. Стенд пайда болғанда анықтама «стендке сәтті орналастыру» болып өзгереді. |
| Өзгеріс | main-ге түскен бір pull request немесе бір коммит. |
| Сәтсіз өзгеріс | Орналастырудан кейін 24 сағат ішінде түзету коммиті не кері қайтару керек болған өзгеріс. docs/ops/incidents.csv журналына жазылады. |
| Коммиттен орналастыруға дейінгі уақыт | Өзгерістің бірінші коммиті мен main-дегі CI-дың сәтті аяқталуы арасы. |
| Қалпына келтіру уақыты | Журналдағы «Басталды» (ақау байқалды) мен «Қалпына келді» (түзету орналастырылды) арасы. |

Деректер көзі: GitHub API (Actions іске қосулары, коммиттер, PR) және incidents.csv. Есептейтін скрипт: scripts/dora.py, іске қосу: Actions → DORA → Run workflow.

## Бұтақ ережесі
- main-ге тікелей push жоқ, тек pull request арқылы.
- PR CI жасыл болғанда ғана біріктіріледі.
- Бұтақ 3 күннен ұзақ өмір сүрмейді. 3 күнде біріктірілмесе, не бөлшектеледі, не жабылады.
- Жобада бір адам, сондықтан ревьюді екінші адам жасай алмайды. Біріктірмес бұрын PR-дағы өзгерістерді «Files changed» қойындысынан өзім қарап шығамын.
