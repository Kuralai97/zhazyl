# Runbook: жазылу беті ашылмайды

Орта: демо-стенд (GitHub Codespaces). Жұмыс ортасына (VPS) көшкенде командалар `docker` командаларымен ауыстырылады.

## Белгілері
- Uptime Kuma «Жазыл — басты бет» тексерісі қызыл (DOWN).
- Браузерде бет ашылмайды, «502», «Server Error (500)» не ұзақ айналып тұрады.
- Тапсырыс беруші не клиент «жазыла алмаймын» деп хабарлайды.

## Диагностика
Барлық команда Codespaces терминалында, жобаның түбір папкасында (`/workspaces/zhazyl`) орындалады.

1. Codespace ашық па: github.com/codespaces бетінде zhazyl codespace-і «Active» болуы керек. «Stopped» болса — оны басып ашыңыз да, 3-қадамнан бастаңыз.
2. Стенд жауап бере ме:
   `bash scripts/stand.sh status`
   «Жауап коды: 200» — стенд жұмыс істейді, ақау браузерде не желіде. «Стенд жауап бермейді» не 500 — келесі қадам.
3. Сервер процесі бар ма:
   `pgrep -fa "manage.py runserver"`
   Ештеңе шықпаса — процесс тоқтаған, «Қалпына келтіру» 1-тармағына өтіңіз.
4. Журналдың соңғы жолдары:
   `tail -n 30 stand.log`
   - `database is locked` — бір мезгілдегі жазулар (ақау D-1). Қалпына келтіру 1-тармағы.
   - `no such table` — миграция жасалмаған. Қалпына келтіру 2-тармағы.
   - `Invalid HTTP_HOST header` — стенд `stand.sh` арқылы емес, қолмен іске қосылған. Қалпына келтіру 1-тармағы.
5. Дискіде орын бар ма:
   `df -h .`
   Use% 95 %-дан көп болса, `rm -f stand.log` жасап, 1-тармақты орындаңыз.

## Қалпына келтіру
1. Стендті қайта іске қосу:
   `bash scripts/stand.sh stop`
   `bash scripts/stand.sh start`
   `bash scripts/stand.sh status` → «Жауап коды: 200» болуы керек.
2. Миграцияларды қолдану:
   `cd src && python manage.py migrate && cd ..`
   содан кейін 1-тармақ.
3. Дерекқор бұзылса (тек стендте, онда нақты деректер жоқ):
   `rm -f src/db.sqlite3`
   `bash scripts/stand.sh setup`
   `bash scripts/stand.sh start`
4. Тексеру: браузерде басты бет ашылады, бір қызметті басқанда бос уақыттар көрінеді.

## Эскалация
- 15 минутта қалпына келмесе: Құралай жұмыс ортасында кері қайтару туралы жалғыз шешім қабылдайды (docs/ops/release-plan.md), стендте — UAT қатысушыларына хабарлап, сынақты басқа уақытқа ауыстырады.
- Әлібекке 15 минуттан кейін бірден хабарланады: не болды, қашан қалпына келеді.
- 1 сағаттан ұзақ тоқтау не деректер жоғалса: docs/ops/incidents.csv-ке жазылады, 3 жұмыс күнінде postmortem жазылады.
